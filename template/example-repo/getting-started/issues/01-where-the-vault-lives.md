## Question

**vault ควรอยู่ที่ไหน และทำไมถึงไม่เก็บ map ไว้ใน repo ที่กำลังทำงานอยู่**

คำถามแรกที่ทุกคนถาม เพราะมันดูขัดสัญชาตญาณ: บันทึกเกี่ยวกับงานใน repo หนึ่ง ทำไมไม่อยู่ใน repo นั้น
`docs/plan/` ก็มีอยู่แล้ว agent ก็เขียนลงไปได้เลยโดยไม่ต้องตั้งค่าอะไรเพิ่ม

ใบนี้ถูกปิดไปแล้วตั้งแต่ตอนคุณติดตั้ง — เก็บไว้ให้ดู**รูปแบบของใบที่ resolve แล้ว** ว่า `## Answer`
ควรมีหน้าตาแบบไหน

## Answer

**vault เป็น git repo แยกของตัวเอง อยู่นอก repo ที่ทำงานอยู่** — ค่าเริ่มต้นคือ
`~/Documents/Git/wayfinder-vault/` และ installer ถามคุณตอนติดตั้งว่าจะเอาไว้ตรงไหน

เหตุผลสามข้อ เรียงตามน้ำหนัก:

1. **map อายุยืนกว่าที่เก็บของมัน** — งานหนึ่งชิ้นมักเดินผ่าน branch หลายอัน worktree หลายอัน
   บางทีข้าม repo · map ที่นอนอยู่ใน `docs/plan/` ของ worktree จะ**หายไปพร้อม worktree**
   ตอนงานจบ ซึ่งคือนาทีที่บันทึก "ทำไมถึงตัดสินใจแบบนั้น" เริ่มมีค่าที่สุดพอดี
2. **map หนึ่งอันมักกินหลาย repo** — เลย์เอาต์ `<repo>/<effort>/` ในนี้จึงเป็นตัวจัดกลุ่ม
   ไม่ใช่ตัวบอกว่าไฟล์อยู่ที่ไหน · effort ที่แตะสอง repo ยังเป็น map เดียวอยู่
3. **repo ของงานไม่ใช่ที่ของบันทึกวิธีคิด** — โดยเฉพาะ repo ที่ส่งให้คนอื่น · สิ่งที่ควรอยู่ใน repo
   คือ ADR ที่กลั่นแล้ว ไม่ใช่ร่องรอยระหว่างทางของการหาคำตอบ

**ผลที่ตามมาที่ต้องรู้ไว้ — ย่อหน้าใน `~/.claude/CLAUDE.md` เป็นที่เดียวที่บอก agent ว่า vault อยู่ไหน**

installer เติมย่อหน้านั้นให้แล้ว **ถ้าคุณตอบตกลงตอนติดตั้ง** · ถ้าตอบปฏิเสธไป `/wayfinder` จะไปทำตาม
กติกาของ repo ที่เปิดอยู่แทน แล้ว map จะไปโผล่ใน `docs/plan/` เงียบ ๆ ซึ่งเป็นอาการที่ไล่หาสาเหตุยาก
เพราะทุกอย่าง "ดูเหมือนทำงานอยู่" — ตรวจได้ด้วย `node _tools/doctor.mjs` ซึ่งมีข้อนี้อยู่

**ที่นี่ไม่ใช่ที่เก็บโค้ด** — vault มีแต่ `.md` กับ `_tools/` · ของแนบยาว ๆ (ผล query, script, log)
วางที่ `<effort>/assets/` แล้วอ้างจากใบด้วย `../assets/…`
